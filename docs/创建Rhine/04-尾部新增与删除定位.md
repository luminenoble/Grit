# 阶段 04：尾部新增与删除定位

前置：[阶段 03](03-两层详情与编辑.md)的两层场景、详情编辑与返回快照可用。

## 目标与任务

完成两层场景中的尾部创建、取消、删除与数据变动后的定位，保持屏幕铺满和真实数据完整。

1. 详情模式中心真实列的有效占位位置触发一次尾插：第一层新增 Task，第二层新增 Section。通过现有仓库保存，取得真实 ID 后更新计数、边界并定位到新增内容。
2. 最后真实列之后仅一列用于新增父对象：第一层新增 Category，第二层在当前 Category 下新增兄弟 Task。其他范围外装饰块无操作。
3. 新 Category 先输入名称、可选文字颜色与描述。保存后定位其 0 号块并结束本次创建；后续点击才创建 Task。第二层新增兄弟 Task 同样先保存 Task，后续点击才创建 Section。
4. A 类别有 100 个 Task、B 只有 1 个时，B 在 U=99 点击占位只新增第 2 个 Task，保存后所有列共用的 U 一起移动到 2；不补齐第 3–99 个数据。
5. 保存中防重复点击；取消或失败不增加计数、不扩大边界、不丢草稿。新增 Section 默认 `unname`，默认完成日期为空，可在创建表单中选择完成并记录当天或过去日期。
6. 整合 Category/Task/Section 删除入口，删除父对象明确告知会删除所属子对象；使用现有仓库级联与排序补位。
7. 删除焦点内容后先选同位置后继，再选前项，列空则回 0；父对象删除时选择相邻父对象或返回上层。删完所有类别时仍保留铺满画面和唯一新建入口。
8. 删除最长列或其尾部内容后即时收缩 U 边界；更新视角时复用统一约束器。新增、删除、重排、Task 更换类别、全量导入后以稳定 ID 重建焦点。
9. Task 页面修改的数据在 Rhine 生效，Rhine 修改的数据在 Task 页面生效；导入后清除过期视角快照，回到新数据有效起点。

## 交付物

- 完整两层创建/删除流程、错误与取消处理、计数和视角同步代码。
- 尾插数量、连续排序、远处追加、最长列删除、空数据回退的测试或设备验证记录。
- Debug APK、`交付/阶段04/实现记录.md`。
- 流程截图：新增 Category 表单及保存后的 0 号块；远处占位新增前后；新建 Section；删除前确认和删除后的位置；全空状态。
- 短录屏展示一次新增保存后的定位和一次最长列删除后的边界收缩，重点保留可观察的前后状态。

## 验收

- 所有新增都是一次尾插，实际数据库对象数符合操作次数，未形成空数据链。
- 真实父对象与尾部新增列在中心时可以辨认；范围外装饰块永远不触发表单。
- 新建 Category 完成后没有自动弹出 Task 表单，第二次操作才新增内容。
- 取消、失败、快速重复点击不产生额外对象或相机跳动。
- 两层都支持删到空、父对象消失、最长列缩短；惯性目标不能继续落在旧边界外。

## 需要用户确认的核心问题

1. 从流程截图看，空块中的新增入口是否容易辨认，是否有容易误触的区域？
2. 创建表单和保存后的移动是否自然，尤其是 U=99 追加到短列第 2 项时是否容易理解？
3. 删除确认、删除后的落点和空类别画面是否清楚，需要调整提示或移动速度吗？

业务仍按已确认的“只追加一个并移动视角”实施，问题集中于入口与反馈的表现。
