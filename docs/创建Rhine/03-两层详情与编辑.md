# 阶段 03：两层详情与编辑

前置：[阶段 02](02-有限浏览与动态起伏.md)的有限浏览、命中与中心焦点可用；读取阶段 01/02 的视觉确认。

## 目标与任务

完成类别层与 Section 层的层级关系、切换动画和已有对象的详情编辑，让用户确认第二层 UI 与操作体验。

1. 接入详情模式；非中心列首次点击只移到中心，该次不打开表单或进入下一层。中心列稳定后点击真实 Task 才进入 Section 层。
2. 第二层列为当前类别内的兄弟 Task，沿列为各自 Section；进入的 Task 在中心。复用现有渲染、窗口、高度、手势和边界模型。
3. 以当前类别的 Task 数 T 和最大 Section 数 S 计算第二层边界：`v∈[0,T]`、`u∈[0,S+1]`。使用 Task/Section 摘要与计数，正文在点编辑时读取。
4. 第一层 0 号块编辑 Category 名称、描述、颜色和适用选项；第二层 0 号块编辑 Task 标题、描述、颜色、完成状态、今天与提醒等。
5. 第二层真实块顶面显示 Section 序号与标题，侧面显示 Task 序号与标题；文字颜色沿用所属 Task。完成日期在焦点信息或详情中可读。
6. 点击 Section 打开现有 Section 编辑器，保存调用 `upsertSection`，校验完成日期并保持身份。Task 完成不改变 Section 日期，Section 全完成不自动结束 Task。
7. 复用 Category/Task 编辑组件与校验；编辑失败保持草稿，提交成功再关闭。确认整页 Task 编辑继续走已有事务保存，不用摘要覆盖完整正文。
8. 进入时保存上层快照，做块升起/靠近与场景过渡；初值可采用总方案的 300–450ms，具体沿用用户对阶段 02 的运动反馈。过渡期间防重复点击。
9. 第二层在焦点信息区的层级路径前提供返回入口，并响应 Android 返回键；返回恢复上层 Category、Task 和偏移。初次进入从 0 号附近展开，再次进入可恢复本会话的位置。
10. 支持当前中心对象被其他页面修改时刷新标题、颜色和位置；对象已不存在时回退有效父级或相邻位置。新增/删除的完整定位流程由阶段 04 接入完善。

## 交付物

- 两层状态与数据适配、详情模式、父对象编辑、单个 Section 保存和切换/返回逻辑。
- 修改后的 Debug APK，`交付/阶段03/实现记录.md`，针对层级、状态恢复和日期/身份保持的验证结果。
- 横屏截图：第一层选中 Task、第二层完整视图、第二层 0 号块、Section 编辑与日期、Category 描述/颜色、Task 描述/颜色。
- 录屏：进入第二层、横向切兄弟 Task、打开并保存 Section、返回原位置。

## 验收

- 兄弟 Task 在同一类别内排列；第二层不是把全应用所有 Task 混到一起。
- Task 与 Section 的序号、0 号块标记和顶面/侧面名称对应正确。
- Task 页面和 Rhine 编辑同一对象后数据一致，长期正文不在浏览时被加载或误覆盖。
- 编辑取消不保存；重复点击不会重复开页/提交；横屏键盘弹出时表单可滚动，不挤掉必需操作。表单以横屏侧边面板或对话框呈现，Rhine 保持横屏。
- 返回恢复原位置，正在过渡时按返回不会留下错层焦点或重复动作。
- 本阶段没有完整接入的新增/排序入口在交付记录中说明，不显示为已经可用的功能。

## 需要用户确认的核心问题

1. 从第二层截图能否清楚理解“每列是一个 Task，块是其 Section”，顶面/侧面的文字层级是否要调整？
2. 层级切换与返回的动画是否自然，速度或位移是否需要调整？
3. 日期、描述和颜色编辑是否方便，详情入口/返回按钮或信息区是否需要调整位置？

这是重点视觉确认点。确认实际第二层画面和表单体验，业务层级沿用已确认设计。
