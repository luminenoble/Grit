# 阶段 05：调整模式与搜索

前置：[阶段 04](04-尾部新增与删除定位.md)完成真实对象操作、有限边界和数据变动后的焦点同步。

## 目标与任务

补齐三种模式、块与整列的排序、目标序号输入及 Task 标题搜索，并让用户确认动态操作体验。

1. 模式按钮按预览 → 详情 → 调整循环，显示当前状态并提示当前操作；两层共用模式。点击、长按、浏览和排序之间明确仲裁。
2. 调整模式长按中心列的真实 Task/Section 沿 U 排序；占位、装饰和新增入口不能拾起或作为排序目标。
3. 第一层长按中心 Category 的 0 号块沿 V 移动整列；第二层长按中心 Task 的 0 号块沿 V 调整兄弟 Task 顺序。
4. 中心列约束应用于拾起时的源对象。拾起之后手势归属于该稳定 ID，可以拖过其他位置；不因经过其他列改变任务归属或编辑目标。
5. 拾起后轻微升高并上下浮动，邻项平滑让位。浮动可从 2–4dp、约 900ms 周期开始，补位可从 200–300ms 开始，最终采用用户反馈。
6. 拖动仅更新界面预览，松手一次提交仓库移动/排序；取消、返回和切换模式恢复未提交状态。持久化失败恢复或重新读取有效数据并提示。
7. 拖至边缘时有限自动滚动，目标只在同级真实对象范围内。整个动画使用正确的最大高度/阴影裁剪和可见窗口，不绘制全部长列。
8. 调整模式点按真实对象可输入“移动到第 N 项”；界面范围为 1..同级真实数量，调用仓库前转换成从 0 开始的位置。0 号块输入的是父对象在同级中的序号。
9. 接入 Task 标题搜索：去首尾空格、英文大小写不敏感、中文子串；结果含类别名和完成标记，分页或限制每页数量。输入防抖，查询在后台，不搜索占位/Section 正文。
10. 选中结果回到第一层预览模式，使所属 Category 与 Task 位于中心；从第二层搜索也遵循该规则。选中时核对最新 ID 与位置，已删除结果合理提示。

## 交付物

- 调整模式、拖动状态、整列移动、让位动画、序号表单和搜索代码。
- 两层内容/父对象重排、越界序号、取消/失败、搜索重名/已删除结果的验证记录。
- Debug APK、`交付/阶段05/实现记录.md`。
- 截图：三种模式、拾起与让位、0 号整列调整、序号输入、搜索结果与定位后的场景。
- 录屏：内容第 8 项拖到第 2 项、Category 整列移动、第二层 Section 排序、边缘有限自动滚动、搜索并定位。

## 验收

- 从第 8 项到第 2 项，中间第 2–7 项后移；反向移动、原位、首尾和输入位置的结果一致。
- 0 号块不会混入 Task/Section 内容列表，拖动不会跨父对象改变归属。
- 松手提交一次，取消不持久化；重启后顺序与操作结果一致。
- 搜索只匹配 Task 标题，包含已完成 Task，重名结果可区分，空结果不扩展场景边界。
- 非调整模式长按不排序，拖动中不打开详情，模式切换不留下悬浮块。

## 需要用户确认的核心问题

1. 三种模式的区别是否足够明确，长按拾起和目标位置是否易于识别？
2. 从录屏看，浮动、让位和边缘自动滚动的速度是否舒适，是否需要更稳或更慢？
3. 序号输入与搜索结果布局是否好用，选中搜索结果后的落点是否明显？
