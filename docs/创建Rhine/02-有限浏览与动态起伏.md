# 阶段 02：有限浏览与动态起伏

前置：[阶段 01](01-静态场景与视觉基线.md)的代码可运行；读取其最后确认的视觉参数与截图。

## 目标与任务

在第一层接入真实只读数据，建立有界、按需的浏览和中心列动态起伏。本期先完成预览模式。

1. 使用 `getCategoriesFlow`、`getCategoryCountsFlow` 及可见类别的 `getTaskSummariesFlow` 接入类别、Task 标题、颜色、完成状态和排序。Rhine 包含全部 Task，不使用“今天”虚拟列或隐藏已完成筛选。
2. 实现沿列 U 与跨列 V 的手势分解、触发距离、方向锁定、惯性和吸附；HUD 控件（U 步进箭头、V 切换箭头等）的点击与场景滑动互斥。
3. 中心列与焦点使用稳定 ID；滑动 U 时主峰连续交接，切换 V 时旧列回落、新列升起。静止时仅一列起伏，避免列间反复抖动。HUD 的焦点信息、沿列读数、刻度和 V 切换随焦点实时更新。
4. 建立统一边界：C 为真实类别数，M 为最大 Task 数，焦点 `v∈[0,C]`、`u∈[0,M+1]`；没有类别时 U 固定在起点。只留一列新增 Category 入口和一格全局尾部空间。
5. 所有类别共用 U 偏移。短列超过其真实内容的位置是范围内占位；逻辑范围之外只为铺屏绘制装饰块，不可聚焦或交互。
6. 实现可见窗口反投影和有限预绘制余量，考虑块高和阴影；请求、构造、绘制、缓存数量随视口而非总数据量变化。数据查询不逐帧发起。
7. 可见顶面和侧面共同参与命中，按实际遮挡从前向后判断；预览点击只定位，不创建/编辑/排序。
8. “回到开头”令 U 回到 0，保留中心类别；窗口尺寸变化（分屏、进入时的横屏切换）后保留对象焦点，重新计算投影和边界。

## 交付物

- 只读数据适配、可视窗口、边界、命中、手势、焦点及动态高度代码。
- 投影/命中、边界限制和数据不均匀场景的针对性测试。
- Debug APK、`交付/阶段02/实现记录.md` 与测试结果。
- 横屏截图：起点、普通中段、尾部、A 有 100 个 Task 而其他列各 1 个时的第 99 个位置、全空数据状态。
- 录屏：U 滑动与峰值交接、V 切列与吸附、甩动到尾部后继续外滑。记录帧率/速度观察所用的设备。

## 验收

- A 有 100 个 Task 时可浏览至位置 101 的全局尾部入口，再往外不能移动。
- U=99 时，短列没有重复出现其第 1 个 Task，没有被补成 99 个数据库对象。
- C=0 与只有一个空类别时画面铺满，但不能无限浏览空区。
- 任意高度的点击命中正确的前景块，被遮住的块不响应。
- 相机边界由真实计数决定；装饰块数量、手机尺寸或绘制余量不会扩展边界。
- 离开页面/进入后台停止无用动画，普通浏览不读取全部正文。

## 需要用户确认的核心问题

1. 从录屏看，滑动、惯性与吸附速度是否自然，是否容易找到当前中心列和焦点？
2. 峰值高度、波峰宽度和切列抬升是否合适，是否需要更缓慢或更克制？
3. 起点/尾部和短列占位的视觉是否清楚，有哪些区域容易误认为是真实内容？

确认视觉与运动效果，不重新询问已确定的有限边界、共享偏移或尾插业务规则。
