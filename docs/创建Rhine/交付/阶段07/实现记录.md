## 实际整合和优化

- `RhineSceneInput` 在新的不可变场景快照创建时计算最长列。每个可视块判定不再反复扫描全部列；位置和数据库边界规则不变。
- 每个 Canvas 保留一个可重用 Path，逐面 rewind 后绘制，替代每块顶面、侧面、端面、描边与双层阴影反复创建 Path。路径没有按数据 ID 累积，随 Canvas 释放。
- 文字布局缓存由128项调整为384项，覆盖当前视口多面文字和短距离往返。仍有固定上限，继续由 Compose 的文字、样式、约束、密度和字体解析结果决定布局失效。没有增加长期标题/正文缓存。
- Debug 内存样例增加 `large`（100 Category ×100 Task）和 `sections1000`（2 Task，Section 1000/1），包含重名、长标题及已完成对象。保留 empty、one-empty、uneven、adjust、detail 等前期样例。
- Debug 设置预览按初始视口取有界摘要，取消无条件预读无关前六列的前100项；业务页面的摘要接口和分块窗口没有改变。
- Debug `RhineMetrics` 记录范围摘要调用、发射、活动订阅、按ID正文读取、可视块分类及 Android FrameMetrics。请求明细最多64条、帧明细最多2048条。生产页面没有安装观察器，所有造数/导出统计命令只存在于 `src/debug`。
- TaskViewModel的完整正文流改为跟随state实际订阅数启停。离开Task或后台暂停其UI观察后取消正文订阅；再次观察重取最新数据。保留上次Task页面快照，避免清空草稿；不修改保存、事务或提醒调度。新增设备测试验证隐藏时更新不触发正文发射、重新观察读到Rhine修改。
- 构建版本改为普通版本号；Beta 后缀不再查询 Git 提交标识。Java21、最多2 worker、Kotlin in-process；全仓 Spotless 沿用WSL限制，定向ktfmt及差异检查另有日志。

帧耗时前后比较及采样边界见[性能报告](性能报告.md)。FrameMetrics包含应用窗口绘制与流水线时间，开发计数器也有额外成本，不能外推成手机 Release 帧率。

## 保持的行为与默认值

两层 Category→Task、同类别 Task→Section；各层0号编辑父对象；稳定ID、连续orderIndex、有限U/V、短列占位、只尾插一个、事务提交、手动Task完成独立于Section日期、返回快照与导入generation失效均保留。正常入口从Koin注入真实TaskRepo，没有以测试样例替换生产仓库。

配置键仍为 `rhine_display_v1`，与业务JSON备份分离。Standard、目标12行/3列、顶面8sp/侧面7sp、长207dp/厚18dp、基础16dp/中心24dp、峰高70dp/峰宽4.5、U间距16dp/V间距12dp。三类序号开启；占位父名称、聚焦滚动、减少动画关闭；阴影Standard。dp与sp各转换一次，目标密度不限制业务对象数量。

没有修改米色、侧面渐变、光照方向、文字对比度、贴面坐标、Gaussian峰值、240ms吸附/让位、360ms层级切换或排序浮动参数；减少动画及系统动画为0继续遵守既有规则。
