# 阶段07性能报告

2026-10-14。结论：本API36模拟器FOSS Debug未达到60Hz，性能目标判为未通过。真实采样已完成，不用历史数据、截图或screenrecord编码fps代替渲染帧率。

## 环境、数据和方法

Windows Android Emulator 37.2.12 / rhine-p0-api36 / Android16 API36 / x86_64 / gfxstream，宿主NVIDIA RTX4060 Laptop与AMD610M由启动日志识别；实际选用设备由模拟器决定，未据此声称独占GPU。WSL约7.8GiB内存，Java21构建。2400×1080、420dpi、fontScale1.0，Standard默认8/7sp、标准双层阴影，减少动画/聚焦滚动关闭。只有模拟器，没有真机或Release实测。

所有数据为单次事务直接写入独立内存Room。large：100类别各100Task（10000），每Task有长描述，10%重名、每4条含1条完成项；初始U50/V49=Category50/Task50。sections1000：1类别2Task、Section1000/1，初始Task1，进入第二层从0号开始；Section长正文每3条包含1条同日完成项。原有empty、one-empty、uneven(100/1/1)和adjust(12/8/1/0/9)由本轮UI/媒体回归覆盖。

进入HUD和仓库就绪后应用配置，读取专用DataStore或inspect-config确认实际字段。large预热5秒；操作专项预热3秒。静止10秒；U轴20次真实adb swipe，每次400ms、交替方向、之后350ms；追加三组相同20次，共80次；尾部10次300ms越界swipe；第二层20次浏览；进入/返回5次；搜索3次；设置预设保存4次；序号排序2↔8共4次。每组先reset计数与gfxinfo，结束读取FrameMetrics/gfxinfo/meminfo。

FrameMetrics TOTAL/DRAW/LAYOUT_MEASURE纳秒转毫秒，剔除FIRST_DRAW_FRAME。每组帧明细最多2048条，本轮各组均未超过上限；Android回调可能丢失帧通知，未统计其dropCount，不能把样本数除以时长当精确fps。TOTAL_DURATION是已渲染帧的流水线耗时，不能代表全部输入到显示延迟。draws仅场景Canvas绘制次数；搜索/键盘/层级graphicsLayer动画可能产生窗口帧而不重绘场景。gfxinfo原文独立存档，定义可能与FrameMetrics不同。

范围统计是TaskRepo有界摘要方法调用、发射和活动分页订阅，并非SQL执行次数；不统计计数/目录查询、单ID摘要或搜索SQL。正文读取统计代理的完整Task/Section接口；生产DAO投影列经代码审查不含description/content。每次检查统计不导出业务正文。

## 有界性与内存

large稳定全屏视口112块，动态最多115块，都是范围内真实块；尾部U101的112块分为真实62、占位5、范围外装饰45。Section样例U2的112块分为0号2、真实15、占位19、新增列12、装饰64。块数依视口/几何而变，不以数据规模决定；64项单元包含100与10000目录规模同视口几何/命中一致的检查。

摘要单页实测上限72个Task，Section浏览上限47；large同时18页。20次浏览1278个页请求相当于71次矩形窗口重订阅（每次18页），对268个已采样窗口帧；单次窗口更新有多个父级分页请求，不能把页请求数直接当逐帧查询次数。现有分块+distinctUntilChanged保持窗口变更驱动，不写数据库；UI排序后仍只提交一个事务。其矩形保守预取仍较宽，是后续优化线索，当前没有删除投影安全余量。

保留缓存容量：TextMeasurer384项、Canvas单Path、Debug请求明细64条、FrameMetrics2048条；缓存占用量与保留项实际数未做堆转储，因此容量不是实测使用数量。未引入按所有Task永久保留的路径/占位列表；Room保存完整隔离数据本身随规模增长，这是数据存储而非可视缓存。

固定80次浏览，PSS采样157253（静止）→179289（首20次）→183190→188284→188932kB，最后一组增加648kB，RSS及Native/Dalvik明细见原文。三轮增量3901/5094/648kB不呈固定增速，但PSS仍上升；据此不能判定“无持续增长”或“无内存泄漏”。更换独立样例后PSS下降不作为同会话泄漏反证。小时级、强制GC后保留集、真机Native/GPU内存专项未验证。

## 整合后隐藏Task页订阅修正

最终增量发现TasksViewModel原先在init永久collect完整getTasksFlow；进入Rhine后Task页已离开但Activity作用域的ViewModel可能仍保留。已按Task state实际订阅数取消/重开正文流，保留历史Task快照以维持返回语义，不在隐身期间反复加载正文。该快照是Task页数据缓存，仍随此前Task数据规模占内存；本次隔离纯Rhine采样没有激活Task页，不能当作包含全部Task页面历史的全应用内存上限。

性能before/after前后样本在本期绘制优化包执行；随后仅增加显式隔离Task页面入口及上述Task正文订阅修正，Rhine Canvas/查询窗口没有再改。最终APK另采静止和同20次浏览，文件前缀final，用于准确关联交付版本；不把早期包结果冒充完全相同二进制。
