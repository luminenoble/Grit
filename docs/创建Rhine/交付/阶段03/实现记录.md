## 交接说明

- 继续复用 `RhineProjection/layoutScene/hitTest`、`RhineBounds`、`RhineBrowser.move/animateTo`、窗口摘要机制。装饰先参与遮挡再拒绝操作，所有列共用 U，不把装饰数作为业务边界。
- `RhineSession` 保存父快照和有限会话缓存；`RhineSnapshot.resolve` 根据当前目录与单项摘要解析位置。Section 层的 `RhineFocus.categoryId` 是 Task 父 ID，`itemId` 是 Section ID，外部所属 Category 由 session.categoryId 保存；不要将两者混淆。
- 返回查询当前 Task 摘要，改归属后跟随新 Category。父类别缺失时回到有效类别层；单个兄弟缺失时限制到有效相邻 Task。阶段 04 仍须完善主动删除的后继/前项定位、尾部新增和保存后定位流程。
- `RhineBrowser.follow` 用于数据更新后按身份定位，`select` 用于用户明确点选；窗口先刷新时保留原焦点 ID，等待单项摘要定位。`restoreEpoch` 使相同 ID 的会话恢复也重新解析位置；外部重排的兼容性不代表 Rhine 排序入口已实现。
- 编辑入口独立读取完整对象；不要用浏览摘要替换描述或 Section 正文。直接 Section 保存与整页 Task 草稿分别沿用原有事务路径。
