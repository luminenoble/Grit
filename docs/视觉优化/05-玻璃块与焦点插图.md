## 焦点 Task 完整插图

- 相机静止、焦点落在有插图的 Task 上时，该块长侧面按完整高度显示插图（与 0 号块相同），280 ms 淡入；减少动效时直接出现。
- 同列前方遮挡它的块变为清玻璃（主体 30% 不透明度），**标题与侧面文字保持不透明**。
- 焦点 Task 优先：若该列 0 号块位于前方并与之重叠，0 号块的插图随 Task 插图淡入而淡出。
- 编辑器、导航过渡和调整拖动期间不显示。只查询焦点前后 3 格内 Task 的插图并提前解码（768 px 档）。

## 玻璃与模糊

| 部分 | 做法 |
| --- | --- |
| 磨砂源 | 每帧把地面、接触阴影、顶面、端面和已展开的插图画进 1/4 尺寸图层，模糊 14 dp；不含长侧面，所以侧面透出的是身后的光，而不是自己 |
| 长侧面 | 先画磨砂源（裁剪到该面），再叠 74% 原色调渐变、顶部光泽和顶边细高光；整体不透明，后方块只以柔光透出，不会出现清晰边线。屏幕边缘的块（居中度 < 0.08）保持哑光 |
| 顶面、端面 | 保持原色，以保证标题对比度 |
| 景深 | 整个场景再画进 1/4 图层模糊 6 dp，以焦点块为圆心径向遮罩：半径 38% 内清晰，向边缘逐渐模糊（最多 90%） |
| 回退 | Android 10–11（无模糊）、“降低透明度”或阴影质量为低/关：保持原哑光外观 |

实现：`RhineCanvas` 中的 `frostLayer`、`frostCache`、`sceneLayer`、`depthLayer`，以及 `drawRhineBackdrop`、`drawRhineScene(reveal, glass)`。从绘制作用域内录制图层时必须传入独立的 `Density`，否则会无限递归（首版在设备上栈溢出）。

## 验证

- 单元测试 80/80（移除插图条的 3 项）；JVM / Wasm 编译通过。
- 模拟器：工作列焦点 05 显示完整插图，前方 01–04 为清玻璃且标题清晰；焦点 01 时 0 号块插图让位；景深模糊在远处列可见。
- 帧耗时（模拟器 Debug，拖动浏览，`gfxinfo` 中位数）：玻璃约 113–133 ms，哑光约 85 ms。首版每个面重复绘制模糊图层时为 200 ms，改为每帧缓存一次后降到现值。模拟器 Debug 本身达不到 60 Hz（阶段 07 已记录），实机与 Release 数据待测。

## 限制

- 前方清玻璃块的边线会叠在插图上，这是玻璃的正常效果。
- 磨砂是近似效果：模糊源每帧只生成一次，不逐块计算真实的背后内容。
