# 阶段 4：第一层 Task 插图条

> 已被[阶段 5](05-玻璃块与焦点插图.md) 取代（D15：移除插图条，改为完整显示焦点 Task 的插图）。本文保留几何检查与方案比较。

日期：2026-10-21。分支 `rhine-task-illustrations`（从 `visual-optimize` @ `72ebbdd` 创建）。前置：[阶段 3](03-Rhine图片与最终验收.md) 的插图存储、解码缓存和贴面绘制，决策 D9、D11。

## 需求

第一层（Category 层）只有每列 0 号块显示 Category 插图。用户在 Rhine 编辑器或 Task 页也能为 Task 选图，但这些图在第一层从不显示，只有进入第二层后作为该 Task 的 0 号块出现。要求：做小改动，让 0 号块后面的 Task 插图也能显示；改动前先检查是否有不可接受的重叠或其他问题。

## 几何检查

图片只能画在块的长侧面（`front` 面）。数值由 `RhineGeometry` 默认值和投影算出（脚本复核），并由真实渲染器离屏渲染确认。

| 量 | 值 | 来源 |
| --- | --- | --- |
| 原插图规则需要的可见侧面高度 | 39.2 dp | 标签带 7 sp × 1.6 + 4 dp，上下各 3 dp，图片至少 18 dp |
| 同高相邻块之间露出的侧面 | 13.0 dp | `gapU / slopeU` = 16 / 1.229 |
| 非中心列 Task 块的可见侧面 | 13.0 dp | 所有块同为 16 dp 高 |
| 中心列 Task 块的可见侧面 | 4.1 – 21.9 dp | `h(u) − h(u−1) + 13`；峰前最大，峰后递减 |
| 焦点块本身 | 14.7 dp | 峰顶两侧几乎等高 |

结论：**Task 块的可见侧面最多 21.9 dp，远低于 39.2 dp**，在现有规则下第一层永远画不出 Task 插图。顶面虽然始终完整可见，但垂直于长边只有约 12.8 dp，还要放标题，不适合放图。

## 方案比较

| 方案 | 做法 | 检查结果 |
| --- | --- | --- |
| A 展开焦点面 | 焦点 Task 有图时按 D11 的方式完整绘制其侧面，前方遮挡块改为 28% 不透明 | **不可接受**：要淡化前方 2–3 个真实 Task 块（u−1 遮住焦点面 z < 95 dp，u−2 遮住 z < 63 dp，u−3 遮住 z < 28 dp），它们的标题和 0 号块的 Category 插图都变成叠在图上的残影 |
| B 抬升焦点块 | 焦点 Task 有图时浮起约 34 dp | 抬升超过 26 dp 就完全挡住下一个 Task（u+1）的标题，超过 34 dp 开始挡 u+2；打破“所有顶面标题可见”的不变式 |
| C 借用 0 号块 | 焦点 Task 有图时，0 号块临时显示它的图 | 无新重叠，但图片出现在 Category 块上，归属被误读；焦点远离列首时 0 号块变矮，图只剩约 20 dp |
| **F 插图条** | 有图的 Task 用插图条替换侧面标签，只画在未被遮挡的部分 | 无新重叠，排列不变，所有 Task 插图同时可见；代价是插图条较细（9–18 dp），峰后两格及更远的块露出不足 10 dp 时不画 |
| F + B | F，再加焦点块抬升显示大图 | 同 B 的标题遮挡问题 |

## 设计

### 规则

```kotlin
fun showsIllustrationStrip(slot: RhineSlot): Boolean =
    slot.kind == RhineBlockKind.Real && slot.item != null && slot.column != null
```

- 只对已存储的条目（第一层的 Task）生效。0 号块、占位块、新建列和装饰块不变。
- 第二层的条目是 Section，没有插图：`RhineScreen` 只在第一层为条目查找插图。
- 被抬升的块（编辑器、新增/删除过渡）仍按阶段 3 的规则显示编辑草稿中的大图。

### 位置与大小

插图条画在侧面的可见部分（`frontVisible`），左右留 8 dp（与文字内边距相同），上下各留 2 dp：

```text
x:0                                                          L
y:0 ┌──────────────────────────────────────────────────────────┐
    │ ┌──────────────────────────────────────────────────────┐ │ ← 2 dp
    │ │             插图条（居中裁剪，圆角 2 dp）               │ │
    │ └──────────────────────────────────────────────────────┘ │ ← frontVisible − 2 dp
    └──────────────────────────────────────────────────────────┘
      ↑ 8 dp                                               8 dp ↑
```

- 高度低于 6 dp 或宽度低于 48 dp 时不画，侧面保留原标签。
- 有插图条时不画侧面标签。该标签只是重复列名（如“02 生活”），列名仍在 0 号块和其他块上。
- 明暗渐变叠加与 0.5 dp 描边沿用 `drawFaceImage`，与 0 号块插图的光照一致。
- 只用侧面未被同列前一块遮挡的部分，所以不会盖住任何其他块的面。较高的中心列从前方挡住后方列某块的端部时，插图条与那一段侧面一起被挡住，这是正常的前后遮挡，原标签也一样（单元测试 `nothingDrawnLaterCoversAStrip`）。

### 加载

| 项目 | 做法 |
| --- | --- |
| 查询 | `illustrationsFlow(Task, ids)`，ids 为已加载窗口内的条目。窗口按 `queryWindow()` 分块变化，不逐帧重新查询 |
| 解码 | 只解码当前可见窗口（`visibleSlots()`）内的插图，防抖 100 ms，使用最小档 384 px |
| 缓存 | 与大图共用 24 MB LRU；每批插图条加载后重新触碰 0 号块的大图，使其保持最近使用，不会被插图条淘汰 |
| 层切换 | `collectAsState` 在流切换后保留旧值，因此查找时再判断一次层级，Section ID 不会误取 Task 的图 |

## 限制

- 插图条是照片的一条横带，主要用于辨认，不是完整照片。完整照片在编辑器和第二层的 0 号块中查看。
- 中心列峰后两格及更远的块露出不足 10 dp，插图条不画；焦点移近后出现。
- 384 px 档在高密度屏上略有放大，插图条很细并叠加了明暗渐变，实测不明显。
- 未验证：实体手机；Section 与 Task ID 相同时的层切换（只经代码审查，夹具中的 Section ID 与有图 Task 不重合）。
