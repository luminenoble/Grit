# 开发与发布

构建、测试、预览和发版的现行做法。流程变化时更新本文。

## 1. 环境（本机 WSL2）

| 项 | 位置 / 说明 |
| --- | --- |
| JDK | 项目要求 Java 21：`export JAVA_HOME=~/jdk-21`（WSL 默认的 17 不行） |
| Android SDK | `~/Android/Sdk`；build-tools `37.0.0`（`zipalign`、`apksigner`、`aapt2`） |
| ADB | 用 Windows 的 `/mnt/d/professionalTools/AndroidStorage/sdk/platform-tools/adb.exe`，Linux 的 adb 看不到模拟器。安装时 APK 先复制到 `/mnt/d/wsl-share` 下，再传 Windows 路径 |
| 模拟器 | AVD `grhinet-visual-api36`（API 36，1080×2400，420 dpi） |
| 用户参考图 | 放在仓库的 `tmp/`，不提交 |

## 2. 构建与测试

```sh
./gradlew :androidApp:assembleFossDebug
./gradlew :androidApp:testFossDebugUnitTest              # 单元测试
./gradlew :androidApp:connectedFossDebugAndroidTest      # 数据库 / 迁移测试，需设备
./gradlew :shared:ui:compileKotlinJvm :webDemo:compileKotlinJvm :webDemo:compileKotlinWasmJs
./gradlew :androidApp:lintFossRelease
```

- 改动 `shared/` 的公共代码后，JVM 与 Wasm 也要编译通过；设置接口变化时同步 Android 实现与 JVM / Wasm 桩。
- 数据库 schema 变化：提高 `TaskDatabase.SCHEMA_VERSION`，加 `@AutoMigration`，提交导出的 `androidApp/schemas/.../N.json`，并补迁移测试。
- 全仓 Spotless 在 WSL 路径下常失败，一般不跑。
- 用户说明“验证由我在设备上完成”时，只做单元测试、编译和必要的模拟器截图，跳过设备测试与 Lint，并在汇报里写明跳过了什么。

## 3. Rhine 预览夹具（仅 Debug）

`com.shub39.grit.rhine.RhinePreviewActivity`（`androidApp/src/debug/`）用隔离的测试库打开 Rhine，不碰用户数据：

```sh
adb.exe shell am start -n com.shub39.grit.debug/com.shub39.grit.rhine.RhinePreviewActivity \
  --es dataset normal --ez detail true \
  --es illustrate "c1=file:///data/user/0/com.shub39.grit.debug/files/t/a.jpg\;t2001=file:///…/b.jpg"
```

- `dataset`：`normal`（默认）、`large`、`sections1000`、`empty`、`one-empty`、`uneven`、`adjust`、`search`、`detail`、`section-uneven`。
- 模式：`--ez detail true` / `--ez adjust true`；`--ez settings true` 打开显示设置。
- 插图：`illustrate` 以 `;` 分隔，`c<ID>` 为 Category，`t<ID>` 为 Task。
- 故障注入：`failSaveOnce`、`failDeleteOnce`、`failMoveOnce`、`failSearchOnce`；`displayConfig` 传显示设置 JSON。
- 截图只放在会话临时目录，不入库。

## 4. 发版

版本号 `X.Y.Z` 对应 `versionCode = XYZ0`（例：6.2.2 → 6220）。分支当前为 `rhine-task-illustrations`。

1. **改版本**：`androidApp/build.gradle.kts` 的 `appVersionCode` / `appVersionName`。
2. **写更新内容**：
   - `CHANGELOG.md` 顶部加一节；
   - `androidApp/src/main/assets/changelog.json` 顶部加一条（英文，应用内“更新内容”读取），删掉最旧的一条，保持 10 条；
   - `README.md` 中的版本号与下载链接；
   - 行为有变化时更新 [Rhine.md](Rhine.md) / [项目概览.md](项目概览.md)。
3. **构建与签名**：

   ```sh
   ./gradlew :androidApp:assembleFossRelease
   BT=~/Android/Sdk/build-tools/37.0.0
   IN=androidApp/build/outputs/apk/foss/release/androidApp-foss-release-unsigned.apk
   $BT/zipalign -c -P 16 -v 4 $IN | tail -1                 # 16 KB 对齐
   $BT/apksigner sign --ks ~/.android/debug.keystore --ks-key-alias androiddebugkey \
     --ks-pass pass:android --key-pass pass:android --out Grhinet-X.Y.Z-foss.apk $IN
   $BT/apksigner verify --print-certs -v Grhinet-X.Y.Z-foss.apk  # v3，SHA-256 901fbd15…
   sha256sum Grhinet-X.Y.Z-foss.apk > SHA256SUMS.txt
   ```

   签名必须沿用这把证书（SHA-256 以 `901fbd15` 开头），否则用户无法覆盖升级。签名产物放在仓库外。
4. **验证**：至少在模拟器上从上一版覆盖安装并启动；schema 变化时确认迁移后数据保留。
5. **提交、打标签、推送**：提交（不含 `tmp/`），`git tag X.Y.Z`，推送分支和标签。
6. **GitHub Release**：`gh release create X.Y.Z Grhinet-X.Y.Z-foss.apk SHA256SUMS.txt --title "Grhinet X.Y.Z" --notes-file notes.md --verify-tag`。说明用中文，写变化、覆盖升级说明和验证范围。
7. 按 `AGENTS.md`：不创建 issue 或 PR。
