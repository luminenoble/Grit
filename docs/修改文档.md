# Grit_Rhine 修改方案

确认日期：2026-10-08。本文是后续实现依据，本次交付为方案文档。

视觉参考：[Rhine_reference.png](Rhine_reference.png)。目标平台为 Android 手机。**Rhine 页面锁定横屏、全屏沉浸显示，画面与版式以参考图为准**（见 [8.6](#86-横屏版式与参考图对照)）；不再做竖屏适配。Task、Setting 等常规页面保持原有方向规则。不单独设计桌面、平板或 Web 版 Rhine。

2026-10-09 更新：原“竖屏为主、横屏可用”改为“Rhine 锁定横屏、复刻参考图”。此前阶段 01 的竖屏截图与只针对竖屏的微调（如“中心列主峰后方的块只显示顶部文字”）不再作为依据，详见[进度与确认记录](创建Rhine/进度与确认记录.md)。

## 1. 产品方向与已确认决定

应用更名为 **Grit_Rhine**，以 `Category → Task → Section` 组织工作。Category 表示工作领域，Task 表示项目、有限任务或长期事项，Section 表示一次具体工作，也允许先记录待办内容、完成后补上日期。Task 页面与 Rhine 页面使用同一份数据。

已确认的规则如下：

1. Section 的完成日期为空表示未完成；勾选时填入当天，可改为过去日期，取消完成则清空日期。同一天可以有多条 Section，可补记过去的工作，排列不强制按日期排序。
2. Task 保留手动完成、“今天”和提醒；全部 Section 完成不自动完成 Task。Rhine 保留已完成 Task 的位置，以小标记区分。
3. Rhine 第一层一列对应一个 Category，列内块对应 Task；第二层一列对应一个 Task，列内块对应 Section，横向显示同类别的兄弟 Task。
4. 点击占位块只在真实尾部追加一个项目，保存后移动视角到新增项目。不给中间位置生成空数据；禁止向无内容区域无限滑动。
5. 文字贴合块面，块体维持米色，采用固定斜视角、柔和阴影和中心列起伏。仅考虑手机，Rhine 只做横屏。
6. 每列起点位于右侧，0 号块在前，真实内容从 1 开始。浏览后部内容时，0 号和第 1 个块允许离屏，通过“回到开头”返回。

底部导航按顺序改为 **Task / Setting / Rhine**。Rhine 页面内隐藏底部导航，由页脚的 `TASK ↗`、`SETTING ↗` 文字入口与系统返回键离开。移除 Habit、原统计栏目及整个项目的 AI 分解功能。原统计栏目中的任务完成率也随栏目移除。

## 2. 当前项目基础与改造范围

当前项目采用 Kotlin、Compose Multiplatform 共享 UI 和 Android Room 数据层。已有功能可以复用，但以下部分需要调整：

| 现有内容 | 当前情况 | 改造方向 |
| --- | --- | --- |
| Task | 有标题、描述、分类、排序、完成状态、提醒、今天标记和 Section 列表 | 增加独立文字颜色和记录时间，统一两种页面的数据操作 |
| Category | 有名称、颜色、排序、隐藏已完成选项 | 增加描述和记录时间，颜色改为类别文字颜色 |
| Section | `name/content/done`，存储于任务的 `steps` 列中 | 增加持久化 ID、排序、完成日期，采用独立表 |
| Section 排序 | 编辑按钮和拖动手柄同时出现 | 任务详情页增加模式切换按钮，两种功能共用右侧位置 |
| 主导航 | Task、Habit、统计、设置 | 改为 Task、Setting、Rhine |
| 主题 | 液态玻璃、分类颜色变体、主题配色设置 | 统一米色，移除整体调色和五种深浅循环 |
| 备份 | Task 与 Habit 混合，含多个旧格式兼容分支 | 改为独立版本的新格式，仅包含新模型 |

保留任务列表、任务详情、提醒、任务桌面小组件、数据导入导出及仍然适用的通用设置。删除 Habit 对应的小组件、提醒、统计、资源和依赖引用，避免仅隐藏入口后仍运行旧业务。

应用显示名称、启动页、关于页面及生成包的名称改为 Grit_Rhine。默认保留现有 Android applicationId 和代码包名，避免仅为更名引入无关的大范围改动。

## 3. 数据模型

### 3.1 标识、排序与时间的统一约定

- 固定 `id` 不随排序改变；数据库使用 Long 主键。新建草稿保存成功后取得正式 ID。
- `orderIndex` 从 0 开始，同一父级内连续排列；界面内容序号为 `orderIndex + 1`。用户输入的是“目标序号”，不是数据库 ID。
- 0 号块是父对象的操作入口，不生成一个编号为 0 的 Task 或 Section，也不占内容排序位置。
- `createdAt/updatedAt` 使用时间点，导出为 ISO 8601 UTC 字符串。修改标题、日期、归属或排序时更新相应对象的修改时间。
- 工作完成日期使用 `LocalDate`，导出为 `YYYY-MM-DD`。时区变化不改变已经记录的工作日期。
- 新增、删除、移动、导入导致的排序变化在数据库事务内完成。

### 3.2 Category

| 字段 | 类型 / 默认值 | 含义 |
| --- | --- | --- |
| `id` | Long | 固定标识 |
| `name` | String，必填 | 类别名称，允许不同类别同名 |
| `description` | String，默认空 | 类别说明 |
| `orderIndex` | Int | 类别排列位置 |
| `titleColor` | 可空 `#RRGGBB` 字符串，默认 null | 类别文字颜色，空值使用默认深灰 |
| `hideCompleted` | Boolean，默认 false | 保留原选项，只作用于 Task 列表和任务小组件 |
| `createdAt/updatedAt` | Instant | 创建和修改时间 |

Rhine 不应用 `hideCompleted`，其位置和序号始终基于全部真实 Task，防止筛选造成位置跳变。类别颜色不再派生 Task 的循环配色。

### 3.3 Task

| 字段 | 类型 / 默认值 | 含义 |
| --- | --- | --- |
| `id` | Long | 固定标识 |
| `categoryId` | Long | 所属类别 |
| `title` | String，必填 | 任务标题 |
| `description` | String，默认空 | 项目或长期事项说明 |
| `orderIndex` | Int | 在所属类别内的位置 |
| `titleColor` | 可空 `#RRGGBB` 字符串，默认 null | Task 独立文字颜色；未设置时使用默认深灰 |
| `isCompleted` | Boolean，默认 false | 手动控制的任务完成状态 |
| `isToday` | Boolean，默认 false | 保留现有“今天”标记语义 |
| `reminder` | LocalDateTime?，默认 null | 保留任务提醒，按现有本地时间规则调度 |
| `createdAt/updatedAt` | Instant | 创建和修改时间 |

领域详情模型可继续提供 `sections: List<Section>`，但数据库不再把整个 Section 列表写入 Task 的 JSON 列。Rhine 概览只读取任务摘要，不读取所有 Section 正文。

Task 完成不改变 Section；Section 完成不改变 Task。长期事项可以一直保持未完成并持续添加工作记录。“今天”是列表中的跨类别视图，不在 Rhine 中生成重复类别。已完成任务不再触发提醒；重新打开任务时只恢复仍然有效的未来提醒。

### 3.4 Section

| 字段 | 类型 / 默认值 | 含义 |
| --- | --- | --- |
| `id` | Long | 跨页面、跨重启稳定的标识 |
| `taskId` | Long | 所属任务 |
| `title` | String，默认 `unname` | 统一使用一个标题字段；编辑界面的标签为 Section name |
| `content` | String，默认空 | 工作内容 |
| `orderIndex` | Int | 在任务内的排列位置 |
| `completedOn` | LocalDate?，默认 null | 完成日期；null 表示未完成 |
| `createdAt/updatedAt` | Instant | 创建和修改时间 |

规则：

- 新增 Section 默认未完成。支持填写内容后直接勾选完成，记录当天工作。
- 完成状态由 `completedOn != null` 推导，不同时保存可独立修改的 `done` 字段。
- 首次勾选使用设备当前日期；补记可以选择过去日期。未来日期不作为完成日期。
- 已完成 Section 编辑正文、标题或排序时保持原完成日期；取消完成清空日期，再勾选使用当日日期。
- 同一天允许多个 Section，不做每日唯一限制。
- 标题保存时去除首尾空白；空标题回退为严格的小写 `unname`。允许重名。
- 序号与标题分开显示，删除或排序只改变序号，不改标题。移除 `section 1/2/3` 自动命名逻辑。
- 第一版 Section 不单设颜色，Rhine 中沿用所属 Task 的文字颜色。

创建、删除 Section 时更新父 Task 的 `updatedAt`，便于跨页面刷新和查看最近修改。完成记录使用小勾和日期呈现，不默认把工作标题整行划掉。

## 4. Task 页面与常规详情编辑

Task 页面保留类别切换、今天视图、新建任务、任务详情和完成操作，统一采用米色背景、深灰文字、轻阴影与清晰层级。

任务详情页保留独立页面形式，进入已有任务时不自动聚焦输入框，不弹出键盘。增加 Task 文字颜色选择，Category 详情增加描述和文字颜色。

Section 列表每行展示：`序号 + 完成按钮 + Section title + 完成日期 + 右侧操作`。标题单行超长时滚动，序号、完成日期和操作按钮保持固定。关闭动态效果时停止自动滚动，编辑器仍能查看完整标题。

在 Section 列表标题附近放置一个独立的“调整顺序 / 完成调整”按钮：

| 状态 | 右侧控件 | 允许的操作 |
| --- | --- | --- |
| 默认编辑 | 编辑图标 | 打开 Section 编辑器，修改 Section name、内容和完成日期 |
| 调整顺序 | 拖动手柄 | 拖动排序，或通过位置操作输入目标序号 |

调整状态下暂停内容编辑和完成切换，避免拖动误触；结束调整后恢复编辑图标。新增按钮统一尾插。Section 编辑器支持保存、取消、删除，并提示删除对象名称。

任务详情使用一个明确的编辑草稿：Section 编辑和排序先更新草稿，点击任务详情的保存按钮后统一提交；返回时如有未保存内容，提示保存或放弃。Rhine 中单独打开 Section 编辑器时，保存只提交该 Section。两条路径调用相同的校验与仓库操作。

移动 Task 到另一个 Category 通过详情中的类别选择完成，在新类别尾部追加，原类别补齐排序；不通过 Rhine 跨列拖动改变归属。

## 5. Rhine 的两层结构

### 5.1 空间和名称约定

为避免“行、列”与屏幕横竖方向混淆，使用两个逻辑方向：

- **沿列方向 U**：从右下延伸到左上，浏览同一父对象内的 Task 或 Section。
- **跨列方向 V**：横跨相邻斜列，浏览 Category，或浏览同类别的兄弟 Task。

每列的 0 号块为起点。第一项真实内容位于 0 号之后，编号 1；不存在前插入口，也不能浏览到起点之前的可交互位置。视口边缘仍由装饰块补满。

| 层级 | 一列对应 | 列内真实内容 | 顶面文字 | 朝向屏幕的侧面文字 | 0 号块 |
| --- | --- | --- | --- | --- | --- |
| 类别层 | Category | Task | Task 序号与标题 | Category 序号与名称 | Category 详情和排序入口 |
| Section 层 | 同类别中的 Task | Section | Section 序号与标题 | Task 序号与标题 | Task 详情和排序入口 |

Category 序号在全部类别中从 1 开始；Task 序号在所属类别内从 1 开始；Section 序号在所属任务内从 1 开始。0 号仅为操作块编号，不改变这些编号规则。

### 5.2 横屏界面控件

Rhine 页面锁定横屏、全屏沉浸（隐藏状态栏与导航栏，边缘滑动可临时唤出），不显示底部三项导航。控件全部采用参考图的文字式 HUD，没有卡片或胶囊按钮；具体位置、字号和映射见 [8.6](#86-横屏版式与参考图对照)。

- 主体为铺满整个屏幕的块体场景，HUD 直接叠在场景上，不加整块遮罩背景。
- 右上角依次为搜索入口、模式按钮和“回到开头”小图标。
- 模式按钮显示当前“预览 / 详情 / 调整”，点击后循环切换，并短暂提示当前操作。
- “回到开头”仅将 U 归零，保留当前中心列。
- 右侧中部为焦点信息区：层级与父对象、焦点编号、完整标题、补充信息和当前模式下的操作。
- 底部为沿列位置（U）、沿列步进、跨列切换（V）和操作提示；页脚提供 `TASK ↗`、`SETTING ↗` 离开 Rhine。
- Section 层的“返回上层”放在焦点信息区的层级路径前；Android 返回键执行同样逻辑，在类别层按返回回到 Task 页面。
- 控件避开刘海/挖孔安全区和系统手势区域；输入与详情编辑使用普通表单，以横屏侧边面板或对话框呈现，键盘弹出时表单可滚动，场景不重新布局。

默认进入预览模式。两个层级共用模式；详情模式进入 Section 层后继续处于详情模式。

### 5.3 进入 Task 与返回

在类别层的详情模式点击中心列的真实 Task：保存当前视角和焦点，将目标块适度升起、靠近，再过渡为该 Task 的 Section 列。兄弟 Task 同时成为两侧的列。首次进入从该 Task 的 0 号与前几条 Section 展开；再次进入可恢复该任务在本次会话中的位置。

切换动画建议初值 300–450ms，期间不接受重复点击或拖动，不重复提交数据操作。返回时恢复上层中心 Category、Task 和浏览偏移；若数据已删除，则选择相邻有效对象并重新限制视角范围。

## 6. 三种模式与 0 号块

### 6.1 预览模式

支持沿 U、V 滑动找内容，松手后平滑吸附到相邻列和块。点击非中心列或偏离焦点的块只做定位；不创建数据、不打开编辑器。长按不启动排序。

### 6.2 详情模式

只操作当前中心列。点击其他列先将其移到中心，该次点击不打开详情、不新增数据；等待视角稳定后再次点击才操作。

| 点击对象 | 类别层行为 | Section 层行为 |
| --- | --- | --- |
| 中心列 0 号块 | 编辑 Category 名称、描述、颜色等 | 编辑 Task 标题、描述、颜色、完成状态等 |
| 中心列真实内容块 | 动画进入 Section 层 | 打开对应 Section 编辑器 |
| 中心真实列内的有效占位位置 | 在该 Category 尾部新增一个 Task | 在该 Task 尾部新增一个 Section |
| 最后真实列之后的一列新增入口 | 新增一个 Category | 在当前 Category 尾部新增一个兄弟 Task |
| 超出逻辑边界的装饰块 | 无数据操作 | 无数据操作 |

新增 Category 必须先填写名称，颜色可不选，描述可为空。保存后定位到新 Category 的 0 号块并结束本次新增，不自动打开 Task 创建表单；之后点击新增块才创建 Task。

Section 层新增兄弟 Task 时同样先保存 Task，定位到其 0 号块并结束此次新增；后续点击才创建 Section。新建表单取消不占用排序、不扩展边界。

### 6.3 调整模式

仅中心列的真实对象可以拾起，占位块不能排序。

- 长按真实 Task 或 Section，沿 U 调整在当前父对象中的位置；不跨父对象移动。
- 类别层长按中心 Category 的 0 号块，沿 V 移动整列，调整类别顺序。
- Section 层长按中心 Task 的 0 号块，沿 V 移动整列，调整兄弟 Task 的顺序。
- “只能操作中心列”约束拾起时的对象。拾起后可以拖过其他位置，手势持续归属于已拾起对象，不因经过其他列而切换编辑对象。
- 拾起后轻微升高并上下浮动；初始浮动幅度建议 2–4dp、周期约 900ms。邻项在目标位置变化时平滑让位，建议 200–300ms。
- 拖至边缘时允许有限自动滚动，范围只覆盖现有可排序对象，不进入新增列或凭空生成位置。
- 松手一次性提交排序；取消、返回、切换模式时还原未提交的拖动，不逐帧写数据库。

调整模式点按真实块可打开“移动到第 N 项”，合法范围为 `1..当前同级真实项目数`。0 号块输入的是该父对象的同级序号，不是把 0 号移入内容列表。

例如从第 8 项移到第 2 项，原第 2–7 项后移一位；反向移动时中间项目前移。确认后保持被移动对象为焦点。首版不做自动按日期、完成状态或颜色重排。

## 7. 占位、追加和有限滑动边界

### 7.1 区分三种块

1. **真实块**：对应数据库中的 Category、Task 或 Section，可以进入详情或排序。
2. **范围内占位块**：位于当前允许浏览的逻辑范围内，用默认米色补齐内容不足的列。在详情模式的中心列中，可触发一次尾部追加。
3. **范围外装饰块**：仅为填满屏幕而绘制，没有业务序号、没有数据库记录、不能成为焦点，也不能点击新增或拖动。

占位块不写入数据库、备份或搜索索引；不会为占位块创建长期存活的对象列表。真实列中的占位块默认不显示文字，可通过设置显示所属 Category 名称；无真实父对象的装饰列始终无名称。

### 7.2 场景范围计算

以下索引表示可吸附的逻辑焦点，不是数据库 ID，也不是屏幕像素坐标。

**类别层：**

- `C` 为真实 Category 数，类别列索引为 `0..C-1`。
- `N[c]` 为类别 c 中全部 Task 数，包含已完成任务。
- `M = max(N[c])`，没有类别时按 0 处理。
- 跨列焦点 `v` 限制为 `0..C`，其中列 C 是唯一的尾部新增 Category 入口。
- 沿列焦点 `u` 限制为 `0..M+1`：位置 0 为操作块；真实内容至 M；M+1 仅预留一格新增空间。
- 某个真实类别 c 中，`1..N[c]` 是真实 Task，`N[c]+1..M+1` 是范围内占位位置。
- 没有任何 Category 时只保留一个新增 Category 入口；限制 U 在起点，不允许沿无内容方向浏览。

**Section 层：**

- 以当前 Category 的真实 Task 数 T 代替 C；以各 Task 的 Section 数代替 N。
- 跨列范围为 `0..T`，尾部只多一列新增兄弟 Task 的入口。
- 沿列范围为 `0..最大 Section 数+1`；同级为空时只保留新建入口。

这是一份数据级边界，不能依据“刚好画出了多少装饰块”反过来扩展。增加显示密度、放大字体或改变块体尺寸也不能增加业务位置。

### 7.3 滑动限制

- 所有列共享同一个 U 偏移，不为短列单独回到起点。
- 直接拖动、惯性滑动、搜索定位、拖动排序自动滚动都经过同一个范围约束器。
- 到达边界后停止位移并终止对应方向的惯性；第一版不做可以逐次扩大范围的越界回弹。
- 允许中心定位到最后一个真实对象以及唯一尾部新增入口；再向外滑动不改变逻辑焦点。
- 各列起点之前、末尾范围之后，为铺满屏幕绘制的装饰块始终不可交互。
- 由于块体斜放和具有高度，像素偏移上限由逻辑范围通过投影求出，不能直接把屏幕宽高当作数据边界。

例如 A 类别有 100 个 Task，B 类别只有 1 个：U 滑到 99 时，A 显示真实第 99 个，B 对应位置显示占位块；B 不会重复绘制它唯一的 Task。全场景最多浏览到尾部新增位置 101，再往外不能移动。

### 7.4 远处占位块上的追加

沿用上例，B 已在中心、U=99 时，详情模式点击占位块：

1. 打开“新增 Task”，父类别明确为 B。
2. 保存时只追加 B 的第 2 个 Task，数据库不会创建第 3–99 个空任务。
3. 保存成功并取得 ID 后，视角移动到 B 的第 2 个 Task，U 对所有列一起更新。
4. 保存失败或取消，则不改变数据、焦点和边界。

新增 Category、Task、Section 均只尾插。新增父对象后定位到其 0 号块；新增内容后定位到该内容块。正在提交时禁用重复保存，避免连续点击造成多个新增项目。

### 7.5 数据变化后重新定位

- 新增成功后重新计算计数与边界，再定位到新对象。
- 删除最长列中的内容后，M 可能变小；收缩边界并将 U 平滑限制到新范围内。
- 删除当前对象时，优先选择原位置的后继；没有后继则选择前项；该列为空则回到 0 号块。
- 删除当前 Category 时，回到相邻 Category；没有类别时显示新建入口。删除当前 Section 层所属 Category 时返回类别层。
- 从 Task 页面修改归属、排序或删除后，Rhine 按对象 ID 重新解析位置，不依赖过时的数组下标。
- 全量导入后清空旧视角快照，从新数据中的首个有效位置开始。

## 8. Rhine 视觉与渲染设计

### 8.1 固定斜视角的块体

采用固定投影的立体绘制：每个块由顶面、朝向屏幕的侧面和另一可见侧面构成。通过一致的光照方向、细微倒角高光、面间亮度差和柔和接触阴影，接近参考图的平滑材质。几何形状由代码生成，不把参考图当背景贴图。

沿 U 的方向严格为右下至左上，与参考图一致：参考图中块的长边（沿 V）向右上倾斜约 29°，同一列的块沿 U 向左上排列（屏幕上约 17°）。使用统一的投影模型：

```text
screenPoint = origin
            + (u - scrollU) * basisU
            + (v - scrollV) * basisV
            + height * basisZ
```

`basisU` 的屏幕 x、y 分量均为负；`basisV` 跨越相邻斜列且与 U 不平行；`basisZ` 表示块体向上升高。绘制、点击命中、拖动位移和滚动边界使用同一份参数。

块体配色以参考图取色为起点（见 8.6 的取色表）：背景/远处约 `#EAE5E1`、顶面约 `#EBE7E4`、长侧面约 `#DCD7CF`、缝隙阴影约 `#C9BBAC`、HUD 文字约 `#100E06`。最终以横屏实机截图与参考图并排对比调节。

优先使用 Compose Canvas 与普通 Compose 控件组合：Canvas 绘制场景，HUD 文字控件和表单保持独立 Compose UI。Compose 提供自定义绘制、变换和文字测量能力；具体块体投影与遮挡由本项目实现。[官方绘制文档](https://developer.android.com/develop/ui/compose/graphics/draw/overview)

### 8.2 中心列高度

所有非中心列在静止时保持基础高度 `h0`。中心列整体抬升，并在靠近视线焦点的块形成一个峰值：

```text
h(u) = h0 + baseLift + peakLift * exp(-((u - focusU)^2) / (2 * spread^2))
baseLift > 0
```

这里是实现建议，不是固定视觉公式；关键约束是：中心列最低块仍高于其他列，只有一个主峰，离主峰越远越低，不能变成所有列随机起伏。

滑动 U 时连续更新 focusU，让峰值自然从一块交接到下一块；停下后最高块与焦点对齐。高度与完成状态、记录数量、日期无关。中心列的 0 号块和占位块同样沿用高度场，保持连续的几何外观。

跨列切换时旧中心列回落、新中心列升起。过渡期间可以短暂同时运动，静止后只保留一列起伏。中心列选择采用吸附和小范围滞后，避免手指停在两列中间时反复切换。

### 8.3 贴面文字和颜色

- 顶面与侧面各自建立局部二维坐标，文字经对应变换后贴合该面，不能仅旋转一行浮在块外。
- 文字裁剪在所属面内，留出边缘内距；不穿透前景块，也不被绘制到错误的面上。
- 类别层 Task 顶面使用 Task 的 `titleColor`，侧面的类别名称使用 Category 的 `titleColor`，两者独立。
- Section 层顶面 Section 标题和侧面 Task 标题沿用所属 Task 颜色。
- 未设置颜色一律使用默认深灰；Task 不自动继承 Category 颜色。
- 用户选色只影响文字，不改变米色块体；移除原五档深浅循环。
- 保存原选色，显示时根据面底色调整过浅或低对比颜色的亮度，尽量保留色相。颜色编辑器同时预览最终贴面显示效果。
- 对比处理以实际顶面、侧面底色分别计算。实现目标为普通文字达到至少 4.5:1 的对比度；无法在保留色相的条件下达到时回退到可读深灰，并在选色预览中直接体现。
- 序号与名称分开布局；长标题只让当前聚焦块在面内缓慢滚动，其余块截断。完整名称在焦点信息区或详情中可读。
- 已完成内容使用小标记，避免整块变色、移除、重新排序或大幅降低文字可读性。

### 8.4 遮挡与点击命中

先生成块体各面的投影，再按空间遮挡关系绘制。不能直接按列表顺序绘制所有顶面，因为升高后的块会遮挡相邻块。高度变化导致冲突时，应进行面级排序与裁剪。

点击按实际可见面的前后顺序反向命中，顶面与可见侧面都映射到同一个块 ID，被遮住的面不响应。先以包围盒筛选候选，再进行多边形命中；手势开始后固定对应对象，避免升高动画改变命中对象。

### 8.5 按需绘制与数据读取

有限数据边界和按需渲染必须同时实现：前者防止滑入无限空区，后者保证大量真实数据时仍然流畅。

1. 将屏幕可视区域反投影到 U/V 范围，考虑最大块高和阴影扩展，增加少量预绘制余量。
2. 只生成该范围内的真实块、占位块和装饰块；超出窗口即释放或复用，不从第 1 项循环到第 10000 项。
3. 概览查询返回 ID、标题、颜色、完成状态、排序等摘要。计数查询用于边界，不加载所有正文。
4. 第二层只查询当前 Category 的兄弟 Task 摘要和可见范围的 Section 摘要。点编辑时再读取完整正文。
5. 根据可视窗口变化更新查询，避免每一帧发起数据库请求；搜索在独立查询中执行。
6. 缓存文字测量、面路径和阴影所需资源。缓存有上限，键包含 ID、标题、字体、尺寸和数据版本，内容变化时正确失效。
7. 滚动中的位置与高度尽量在绘制阶段读取，避免让整个应用反复重组；不在帧循环中排序全部数据或写入存储。
8. 静止时停止不必要的动画；离开 Rhine、应用进入后台时停止场景动画。仅聚焦标题和正在拖动的块需要持续动画。

上述性能方案由项目自行实现，需结合实机分析验证；Compose 官方建议减少高频状态带来的额外工作，并尽可能延后状态读取。[官方性能实践](https://developer.android.com/develop/ui/compose/performance/bestpractices)

## 9. 手势、搜索和焦点状态

### 9.1 手势仲裁

初始滑动达到触发距离后，将屏幕位移转换到 U/V，并依据主要方向锁定本次浏览轴，避免斜向手势同时误切类别和任务。轻点、滚动、长按排序和浮动按钮互斥；开始滚动后取消本次点击候选。

长按排序仅在调整模式启动；排序方向根据对象确定：内容块沿 U，0 号块沿 V。拖动中不切换模式、不打开编辑器。使用有明确状态转换的指针处理，不把多个互相抢占事件的识别器简单叠加。[官方手势文档](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/understand-gestures)

Rhine 锁定横屏，按屏幕密度换算绘图参数。进入页面时的方向切换、分屏或窗口尺寸变化时重新计算投影与可视窗口，保留焦点 ID 并重新限制偏移；不把旧尺寸的像素偏移直接用于新尺寸。

### 9.2 搜索

- 只搜索 Task 标题；去掉查询首尾空格，匹配不区分英文大小写，支持中文子串。
- 搜索全部真实 Task，包括已完成任务；不搜索 Category 名称、Section 内容和占位块。
- 结果显示 Task 标题、所属 Category 和完成标记，区分重名任务。
- 输入采用短暂防抖，查询在后台执行，结果分页或设单页数量，按 Category 顺序、Task 顺序稳定排列。
- 选择结果后进入类别层，把目标 Category 放到中心、目标 Task 放到视觉焦点，并进入预览模式；用户切换详情后可以打开它。
- 从 Section 层搜索也返回类别层定位。搜索结果选中时重新检查 ID 是否存在、是否移动过，使用最新位置。
- 没有结果时显示空结果提示，不创建新列、不扩展边界。清空搜索不删除或筛掉场景内的数据。

### 9.3 状态划分

建议状态中至少包含 `layer`、`mode`、`centerParentId`、`focusedItemId`、`scrollU/scrollV`、`viewportConfig`、`dragState`、`transitionState` 和上层返回快照。

已保存的业务对象由仓库提供；拖动预览、临时高度、相机位置属于界面状态。导航返回快照按稳定 ID 恢复，横屏切换、分屏尺寸变化和进程重建后重新校验对象与边界，不恢复半途的拖动或重复提交保存操作。

## 10. 设置与默认参数

固定米色主题，移除动态取色、整应用强调色、调色板选择和原深浅变体设置。保留通用字体、时间格式、通知、语言、备份等仍适用的设置。Rhine 显示参数集中在 Setting 中，可恢复默认值。

| 设置 | 初始建议 | 约束 |
| --- | --- | --- |
| Task / Section 顶面字体 | 14sp | 可调，兼顾系统字体缩放 |
| Category / Task 侧面字体 | 12sp | 独立可调，避免侧面过小无法阅读 |
| 场景密度 | 标准：与参考图一致，约 3 列、沿列可见 10–14 块 | 横屏适配目标，含屏幕边缘部分露出的块 |
| 密度预设 | 宽松 / 标准 / 紧凑 | 根据手机可用尺寸推导块长宽 |
| 高级块体参数 | 长度、宽度、基础高度 | 设合理上下限，禁止零值、负值和极端密度 |
| 高度起伏 | 整列抬升、峰值高度、峰宽 | 保持中心列最低高度高于非中心列 |
| 间隙 | 沿列间隙、跨列间隙分别调节 | 不能小到无法辨别相邻块 |
| 序号显示 | Category / Task / Section 分别开启 | 关闭文字序号不改变真实排列和 0 号入口功能 |
| 占位块显示父名称 | 默认关闭 | 第一层为 Category 名称，第二层为 Task 标题；无真实父对象时始终不显示 |
| 长标题滚动 | 默认开启 | Rhine 仅聚焦块滚动；普通 Section 列表在可见范围内滚动 |
| 减少动态效果 | 默认关闭，尊重系统减少动画设置 | 关闭浮动和自动跑马灯，切换使用短淡入或直接更新 |
| 阴影质量 | 标准 | 可降低阴影成本，不改变数据数量或交互范围 |

“行列数量”代表希望屏幕容纳的密度，不限制真实数据总数，也不直接扩大滑动范围。密度模式按目标行列数量计算尺寸；用户手动修改高级长宽后切换到自定义尺寸模式，实际可见行列数作为结果展示，避免两套参数互相覆盖。

0 号块在隐藏序号时仍显示明确的父对象名称和操作标记。用户调整参数时实时预览，保存后持久化；重置仅重置 Rhine 显示参数。

## 11. 数据层、备份与原始数据处理

### 11.1 新数据库结构

建议新建 `grit_rhine_database`，采用独立的新 schema 版本，包含 Category、Task、Section 三张表。外键关系为 `Task.categoryId → Category.id`、`Section.taskId → Task.id`，删除父对象时级联删除子对象。

为类别顺序、`Task(categoryId, orderIndex)`、`Section(taskId, orderIndex)` 添加查询索引。Section 单独存储，便于局部更新、范围查询及读取日期，不再反复改写 Task 的整段 JSON。

仓库提供以下统一操作，由 Task 页面和 Rhine 共用：

- 查询类别/任务/Section 摘要、各父对象的真实数量、可见排序区间。
- 按 ID 读取完整详情；按 Task 标题搜索；查询目标 ID 的最新父对象和排序位置。
- 尾部新增，返回正式 ID 与最终位置；详情更新；删除；完成状态和完成日期修改。
- 移动到目标序号，在一个事务中完成受影响区间的补位。
- Task 更换 Category 时，同时维护新旧类别顺序，Section 继续跟随原 Task ID。
- 任务详情草稿的整体保存，事务内合并 Section 新增、修改、删除和排序。
- 导入前校验、事务替换数据、导出一致的数据快照。

同一排序操作、删除、整页保存、批量导入完成后再刷新任务小组件和相关通知，避免每移动一个条目都触发一次全量刷新。

### 11.2 原始数据迁移约定

**关于原始数据迁移部分，不用考虑 Habit 的迁移。后续由用户提供导出的 JSON，再将该文件修改为新的兼容格式后导入即可，应用只需要支持新的格式。**

具体落实为：

1. 新版导入器只识别新格式与明确的新格式版本，不保留旧 `steps` 字符串、`name/content/done` 或 Habit schema 的兼容分支。
2. 旧 Task/Category 的必要转换在应用外完成。用户尚未提供旧 JSON，本次不生成或臆造其转换结果。
3. 旧 `done=true` 但没有工作日期的数据，不能把导入日伪装成真实完成日期；外部转换时根据实际文件和用户提供的信息处理。
4. 使用新的数据库文件避免在升级时破坏旧数据库；旧文件不参与新版业务，不自动解析或迁移。首次启动新版空库时明确引导导入新格式。
5. 不静默清空旧库，也不把“只支持新导入格式”误实现为破坏性数据库升级。新库后续自己的 schema 演进仍应正常维护。
6. 系统备份规则改为只包含新的有效数据和配置，避免继续备份已废弃的 Habit 库；遗留文件清理与业务切换分开处理。

### 11.3 新导入导出格式

备份格式版本与 Room 数据库版本分开。建议第一版使用以下结构；数组中的排序以 `orderIndex` 为准，Section 嵌套在 Task 内，导入时由父 Task 填充数据库中的 `taskId`。

```json
{
  "format": "grit_rhine",
  "formatVersion": 1,
  "exportedAt": "2026-10-08T14:00:00Z",
  "categories": [
    {
      "id": 1,
      "name": "学习",
      "description": "持续积累的学习记录",
      "orderIndex": 0,
      "titleColor": null,
      "hideCompleted": false,
      "createdAt": "2026-10-08T12:00:00Z",
      "updatedAt": "2026-10-08T13:00:00Z"
    }
  ],
  "tasks": [
    {
      "id": 10,
      "categoryId": 1,
      "title": "学习 Kotlin",
      "description": "每天记录实际完成的内容",
      "orderIndex": 0,
      "titleColor": "#435B64",
      "isCompleted": false,
      "isToday": true,
      "reminder": null,
      "createdAt": "2026-10-08T12:00:00Z",
      "updatedAt": "2026-10-08T13:00:00Z",
      "sections": [
        {
          "id": 100,
          "title": "完成协程练习",
          "content": "练习取消和异常传播。",
          "orderIndex": 0,
          "completedOn": "2026-10-08",
          "createdAt": "2026-10-08T12:00:00Z",
          "updatedAt": "2026-10-08T13:00:00Z"
        }
      ]
    }
  ]
}
```

数据备份包含颜色、描述、完成日期、排序、提醒和今天标记；占位块、相机位置和动画状态不导出。第一版 Rhine 显示设置保存在本机，不属于上述数据备份，备份界面说明这一范围。

导入流程：读取文件 → 校验格式版本、字段类型、正整数 ID、引用关系、颜色、日期和同级排序 → 显示项目数量和替换说明 → 用户确认后在一个事务内替换新库中的数据。

- 同一对象类型不允许重复 ID；所有 Task 必须引用文件中的有效 Category。
- 同级 `orderIndex` 必须是从 0 开始的连续整数；外部转换工具负责补齐，导入器对错误明确报错。
- 空 Section 标题按 `unname` 规范化；未知格式版本不尝试按旧字段猜测。
- 导入校验或写入失败时保留原新库数据，不出现半批成功。读取大文件、校验和写入在后台执行。
- 第一版只做完整替换，不提供按旧 ID 猜测的合并导入；导入页面展示影响，允许取消。
- 数据提交成功后取消过时的任务提醒、重新安排有效未来提醒并刷新小组件；提醒调度失败可重试，不能让数据库处于半导入状态。
- 导出使用一致快照，保证不会取到重排或整页保存中途的数据。

## 14. 验证与验收标准

### 14.1 数据与常规页面

- Category 可以保存名称、描述、文字颜色；Task 可以独立设置颜色，未设置时为默认深灰。
- 新 Section 标题为 `unname`，左侧序号从 1 开始；重排后标题不被改写。
- Section 勾选填入当天，补记日期正确，取消后清空；同一天多条记录正常。
- Section 全部完成不自动结束 Task；Task 完成不改动 Section 日期。
- 编辑/排序切换时每行右侧只显示当前模式的操作，长标题可完整查看。
- Task 页面与 Rhine 修改同一对象后立即一致，任务详情取消草稿不产生部分保存。
- 今天视图、任务提醒、已完成显示选项和任务桌面小组件按保留规则工作。

### 14.2 空数据、边界和不均匀数据

- 0 个 Category：屏幕仍有米色块，只有一个明确的新建类别入口，不能无限滑动。
- 1 个空 Category：可以创建第 1 个 Task；新建 Category 不自动创建 Task。
- 一个 Category 有 100 个 Task，其余只有 1 个：U=99 时其他列显示占位，不能重复显示它们的真实第 1 项。
- 在短列远处占位位置新增，仅追加一个真实 Task，成功后定位过去，数据库中没有大量空任务。
- 到达全局尾部新增入口后继续拖动或快速甩动，焦点不越界、场景缓存不持续增长。
- 超出边界但为了铺屏而绘制的装饰块，任何模式下均不触发新增或排序。
- 删除最长列的最后内容或删除整个最长列，视角边界立即收缩；不会停留在已失效的无限空区。
- Section 层对同样的空数据、长短列和删除情形应用相同规则。

### 14.3 交互与视觉

- 块体从右下向左上延伸，稳定时只有中心列起伏；其最低块仍高于其他列。
- Rhine 锁定横屏、全屏沉浸，无底部导航；与参考图同尺寸叠图时，块方向、比例、中心墙和 HUD 位置一致。
- U 滑动时峰值顺势交接，V 切换后旧列回落、新列升起，停止后无反复抖动。
- 顶部和侧面文字贴面且被正确裁剪，点击最前方可见面命中正确对象。
- 非中心列第一次点击只定位；详情和排序不会误操作其他列。
- 0 号块可编辑父对象描述及颜色，且能调整父对象同级顺序。
- 拖动从第 8 项到第 2 项，原第 2–7 项顺次后移；反向、相邻移动、原位移动、取消操作均正确。
- 拖动中滑动补位流畅，输入目标序号行为一致，输入越界值不能保存。
- 返回上层、搜索跳转、切换模式、进出 Rhine 时的横竖屏切换、通过页脚离开 Rhine 均不重复提交或丢失已保存修改。
- 横屏下大字体、长中文标题、同名 Task、刘海/挖孔、系统手势区域和软键盘不会遮住必需操作。

### 14.4 导入导出与删除功能

- 新格式导出再导入，ID、归属、排序、描述、颜色、完成日期、今天标记和提醒一致。
- 旧格式、未知版本、重复 ID、孤立引用、非法日期、错误排序和损坏 JSON 均有明确失败提示，原数据不变。
- 新库首次启动不自动读取 Habit 或转换旧 Task，不破坏旧数据库文件。
- 全仓代码引用、依赖注入、Manifest、小组件和资源检查无有效 Habit/统计/AI 入口；历史版权或版本记录按语义判断，不机械删除无关文字。

### 14.5 性能和检查方式

为投影/命中、范围约束、重排补位、日期规则和事务导入编写有实际业务断言的测试。结合 Android UI 测试与实机手动操作验证动画、贴面文字、触摸范围和导航恢复。

建议使用包含 100 个 Category、累计 10000 个 Task、单个 Task 含 1000 个 Section 的测试数据，并包含大量空列和少量长列。验收重点是：单帧绘制量随视口规模变化；概览不读取全部正文；滚动和搜索不阻塞主线程；连续往返浏览后缓存与内存不无界增长。

在指定 Android 手机上以 60Hz 流畅交互为调优目标，记录设备、系统、数据规模、帧耗时和内存。性能达不到目标时优先减少阴影成本、优化文字缓存和查询窗口，不牺牲真实数据或允许无限占位渲染。

实施阶段运行相关单元测试、数据库事务/导入测试、项目格式检查和 Android 构建；共享代码改动同步检查受影响 source set。本次仅新增方案文档，不把这些尚未执行的实现验收记为已通过。
