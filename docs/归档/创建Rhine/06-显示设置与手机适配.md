# 阶段 06：显示设置与手机适配

前置：[阶段 05](05-调整模式与搜索.md)核心交互可用，前期确认的视觉和动画参数已经记录。

## 目标与任务

把已确认的效果做成可调、持久化的手机体验，并通过实际参数对比截图确认默认值与可读性。

1. Setting 增加 Rhine 显示设置，复用现有导航与设置架构，建立默认值、参数校验、存储和恢复默认操作。
2. 顶面与侧面字体大小独立可调，兼顾系统字体缩放；长标题滚动只作用于当前聚焦块，完整标题仍可在焦点信息或详情查看。
3. 提供宽松/标准/紧凑密度预设与目标行列数量；标准即阶段 01 确认的参考图密度（约 3 列、沿列可见 10–14 块），作为横屏适配目标而不是数据上限。
4. 自定义块长、宽、基础高度、中心列抬升高度、峰值和峰宽，以及 U/V 间隙，设合理上下限。自定义尺寸后实际可见行列数作为结果展示，避免与密度输入互相覆盖。
5. Category、Task、Section 序号显示分别切换；0 号入口始终可辨识。占位是否显示父名称默认关闭，无真实父对象的装饰列不显示名称。
6. 实现长标题滚动开关、减少动态效果及阴影质量设置。减少动画时仍保留焦点/排序状态反馈，并尊重系统动画设置。
7. 用户选择的原始文字颜色仍存储为 #RRGGBB，按实际块面底色处理可读性；预览呈现最终显示效果。颜色不扩展成整应用主题调色。
8. 参数变化实时预览，保存后重启保持；只重置 Rhine 显示配置，不改业务数据或其他设置。第一版数据 JSON 备份仍不包含这些本机配置。
9. Rhine 始终横屏。支持小尺寸横屏、长宽比不同的手机（如 16:9 与 20:9）、大字体、刘海/挖孔、键盘和沉浸模式下临时唤出的系统栏；尺寸变化时依稳定 ID 恢复焦点，并重新计算窗口、命中与边界。HUD 按 8.6 的比例定位，在不同长宽比下不重叠。调密度不会把尾部变成无限区域。
10. 设置接口变化同步更新 Android 实现与 JVM/Wasm stub，保持现有 source set 编译。

## 交付物

- Rhine 配置模型、设置 UI、持久化、实时预览、默认与重置代码。
- 密度/自定义模式、非法参数、重启恢复、重置范围的测试或验证记录。
- Debug APK、`交付/阶段06/实现记录.md`，列出最终默认值与调节范围。
- 截图：设置页；同一数据和焦点下的宽松/标准/紧凑；小尺寸横屏默认；16:9 与 20:9 横屏；大字体；隐藏序号；占位名称开启；浅色文字的实际显示。
- 配置更改与恢复默认的短录屏，展示设置如何影响同一场景。

## 验收

- 同一对比组的父对象、内容、焦点一致，仅参数变化，使用户能比较真实效果。
- 设置不会修改计数、顺序、完成日期或 JSON 格式；重启后参数持久化。
- 极端参数仍能访问必需操作，文字不跑到面外，触摸命中随几何同步更新。
- 隐藏序号不改变排序或入口功能；减少动态效果不妨碍完成操作。
- 键盘、旋转、后台恢复不会把焦点或惯性目标移出边界。

## 需要用户确认的核心问题

1. 三组密度截图中，哪一种最适合作为默认，标准字号是否清楚且不拥挤？
2. 设置页面的分类、滑杆/输入与预览是否容易理解，有没有需要合并或调整的控件？
3. 小尺寸横屏、不同长宽比和大字体截图中是否存在需要修改的布局，序号及占位名称的默认显示是否满意？

这是重点视觉确认点。优先确认默认效果，再保留可调参数供个人使用；已经确认的业务与有限边界不随设置改变。
