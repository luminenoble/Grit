# 阶段 07：性能与完整验收

前置：[阶段 06](06-显示设置与手机适配.md)功能完成；收集阶段 01–06 最后确认的截图、默认参数和未解决事项。

## 目标与任务

完成整合、性能和回归验收，交付最终 APK 及可供用户检查的完整证据。前阶段只编译或缺设备的检查本期补齐；不可执行的项目单独列为未验证。

1. 对照总方案检查全部 Rhine 功能与阶段交付，处理跨阶段接口不一致、失效快照、重复保存、旧样例入口和错误提示。
2. 验证两层投影、面级遮挡、贴面文字、命中、中心峰值、模式、0 号块、创建、删除、重排、搜索、设置及返回恢复。
3. 使用隔离的数据集覆盖 0 类别、1 个空类别、长短列 100/1、100 个类别累计 10000 个 Task、单个 Task 1000 个 Section、长标题、重名与已完成项目。
4. 记录可视块数量、摘要请求、文字/路径缓存与内存；连续往返和反复到尾部后不能无界增长。概览不读取全部正文，操作不逐帧写库。
5. 在 Android 手机上测量帧耗时、卡顿和内存，以 60Hz 流畅交互为调优目标，附设备/系统/配置/数据规模和工具。区分测试实测与目标，不用静态截图证明帧率。
6. 优化优先从窗口计算、请求节流、缓存和阴影成本入手，保持用户已确认的风格与业务规则。若明显改变视觉或操作速度，提供前后图/录屏给用户确认。
7. 运行现有模型测试、设备仓库测试及新增 Rhine 逻辑/UI 测试。核验 Task 与 Rhine 数据互通、JSON 导入后焦点失效处理、任务提醒、开机/时间变化恢复和任务小组件。
8. 使用 Java 21 构建 Android APK、编译受影响 source set 并做格式检查。正式业务入口使用真实仓库，开发样例与性能统计按开发构建隔离。
9. 汇总各期用户确认、最终默认参数、已知问题、尚未验证事项和运行步骤；更新实现工作记录与必要 README。

## 验收矩阵

| 类别 | 必须检查 |
| --- | --- |
| 空/不均匀数据 | 0 类别、空列、100/1 数据、远处只追加一个、删最长列、尾部惯性被限制 |
| 两层和 0 号块 | 名称/序号对应、兄弟范围正确、父详情、整列顺序、返回原焦点 |
| 数据一致性 | 稳定 ID、连续顺序、单次事务、取消/失败恢复、同日多记录、跨页面更新 |
| 动态交互 | 只从中心拾起、浮动/补位、边缘有限滚动、过渡防重入、减少动画 |
| 手机布局 | Rhine 锁定横屏与沉浸、离开后其他页面方向恢复、与参考图叠图、小尺寸/不同长宽比横屏、大字体、刘海、键盘、系统栏、后台/重建恢复 |
| 性能 | 可视窗口有界、缓存上限、无逐帧查询/写库、长时间浏览内存、实际帧耗时 |
| 既有功能 | Task、提醒、小组件、JSON 往返；旧 Habit/统计/AI 未恢复 |

设备条件仍不可用时，交付构建、可执行测试和全部复现步骤，明确哪些截图/录屏/性能数据没有取得；状态保留为待设备验证，不写成完整实机验收通过。
