# 阶段 7：光盘玻璃、全部插图与编辑器背景

日期：2026-10-27。分支 `rhine-task-illustrations`。发布 6.2.2。在[阶段 6](06-透明玻璃与文字颜色.md) 的透明玻璃与两次绘制上修改。

## 需求

1. 块太模糊，且只有中心块显示图片。所有有插图的块都要显示，中心块以外的模糊处理，而不是不显示；块要有类似光盘和玻璃的质感，而不只是模糊。
2. Rhine 编辑时，单独抽出的块也用上述质感；编辑界面太空旷，用 Rhine 的方块阵列作背景。
3. 验证从简，主要由用户在设备上完成。

## 决策

| # | 决策 | 结果 |
| --- | --- | --- |
| D21 | 哪些块显示插图 | 所有有插图的块都展开整块长侧面显示：列首块（第一层为 Category，第二层为 Task）和第一层的全部 Task。取代 D14“只完整显示焦点 Task” |
| D22 | 光盘质感 | 玻璃面上加一层薄膜虹彩：每个面一条窄的青、紫、粉、琥珀色带，相位随块在屏幕上的位置变化，移动镜头时色带在块间滑动；另加屏幕上固定的窗光反射、白色边缘高光和长侧面上沿内侧的一条棱镜色线 |
| D23 | 编辑器背景 | 编辑时，其余块不再淡出，而是由转动、放大后的场景交叉淡入为进入编辑器前的总览阵列（正常视角，抽出块的位置空着），轻度模糊并加一层淡地面色。哑光回退下不模糊，遮罩更重 |

## 实现

| 部分 | 做法 |
| --- | --- |
| 插图范围 | `showsIllustration`：列首块、带条目的 Real 块（Section 没有插图）、抬起的块。`openedFaces` 对每个有图的块展开整块长侧面；同列前方的块按画家序正常遮挡，玻璃下仍透出后方图片 |
| 读取与解码 | 读取中心列左右各 3 列的列首插图，以及这些列中焦点前后 8 格的 Task 插图。焦点前后 1 格按原尺寸档解码，其余（处于模糊中）用最小档 384 px。缓存上限 24 MB → 48 MB |
| 模糊 | 近处 3 dp → 1.5 dp，远处 10 dp → 5 dp；径向遮罩从半径 22% 改为 30% 开始，半径由 0.6 W 增至 0.7 W |
| 玻璃面 | 更通透：顶面白 72%→58%，长侧面 42%→26%，端面 52%；折边加深到 35%。虹彩 `RhineStyle.sheen`（约 20–24% 不透明度，`TileMode.Mirror` 循环，周期为面长的 0.85），顶面与端面减弱 |
| 光 | `drawGlassLight` 画在插图之上：窗光（屏幕固定的约 65° 斜带，一宽一窄）、近顶边与端面上沿的白色高光、长侧面上沿内侧的棱镜色线 `RhineStyle.prism` |
| 哑光回退 | 不加虹彩和光；同样展开全部插图。焦点 Task 停稳后，其前方的块仍变为清玻璃（D14 的做法保留，只在哑光下） |
| 编辑器背景 | `RhineFrame.contextAlpha` 改为 `backdrop`（0 总览、1 编辑中）：进入 1100–1350 ms、退出 200–500 ms 过渡。`RhineCanvas` 在 `backdrop > 0` 时另用中性位姿排一份总览布局，与当前位姿的场景按 `backdrop` 交叉淡入，整体进入模糊层：远处模糊在编辑中为 3 dp 且覆盖全屏，再盖 10% 地面色；抽出的块清晰地画在最上层 |

## 验证

- 单元测试通过：插图范围改为“列首、条目和抬起的块”，编辑器帧改为检查 `backdrop`。
- 模拟器 `grhinet-visual-api36`（Debug，预览页加测试插图）简单查看：所有有图的块都显示图片，选中块清晰、其余轻度模糊；虹彩首版过重（整幅泛彩），收窄为每面一条色带并降低不透明度；编辑器背景首版取放大后的场景，只剩几块巨大的模糊色块，改为总览阵列。
- 未测：实体手机、帧率、哑光回退外观。

## 限制

- 同列有图的 Task 叠在一起时，每块只露出未被前方块挡住的上部，类似参考图中的条带；完整图片只在选中块上清晰可见。
- 虹彩与窗光是二维近似，不随真实光源或设备姿态变化。
